二、总体架构

沿用四层架构：pywebview 外壳（主窗口 + 动态壁纸窗口）→ 前端界面（编辑器 / 壁纸中心 / 设置 三页签）→ 本地服务（HTTP + 系统控制）→ 本地存储（配置 / 壁纸库）。

新增模块：

  • core/win32.py — ctypes 封装系统 API：设壁纸、锁屏、显示器枚举、全屏检测、电池检测、WorkerW 查找
  • core/config.py — 全局配置 JSON（定时切换、节能、动态壁纸状态）
  • core/scheduler.py — 定时切换线程
  • core/generate.py — Pillow 程序化生成精选壁纸 + dHash 以图搜图
  • core/dynamic.py — 动态壁纸引擎：每显示器一个透明无边框窗口，重定向进 WorkerW，支持点击穿透/交互模式切换
  • wallpapers/ — 壁纸库目录（user 用户导入 / builtin 内置生成 / dyn 动态模板 HTML）

三、分期交付

1

系统壁纸能力（本期先交付）

静态壁纸一键设置（4 种显示模式 + 跨屏拼接）、锁屏壁纸、定时切换（间隔/顺序/随机）、壁纸中心（内置精选 30 张生成壁纸 + 文件夹导入 + 网格预览 + 快捷操作）、设置页（节能开关、定时规则）。

2

动态壁纸引擎

WorkerW 后台渲染窗口（每屏独立）、内置动态模板（极光/星空/粒子/波浪/时钟/雨滴）、点击穿透与交互模式、节能模式（全屏应用 / 电池触发暂停）、动态壁纸定时切换。

3

编辑器动效 + 按图检索

编辑器新增元素动效（浮动/旋转/脉冲）、粒子系统、鼠标拖尾、点击事件，导出动态壁纸包（HTML）并由引擎播放；本地 dHash 以图搜图。

四、关键风险与对策

风险对策
WorkerW 重定向导致 pywebview 窗口渲染异常先验证最小窗口重定向；异常时回退为「置底 + 点击穿透」窗口（图标层之上）并给出提示
锁屏壁纸注册表需要管理员权限尝试写入，失败返回可读错误 + 管理员运行指引
动态壁纸常驻 CPU 占用节能模式默认开启；动画帧率上限 30fps；模板提供低功耗档位
跨屏拼接在不同缩放比显示器失真按虚拟桌面逻辑坐标拼接，DDI 缩放交给系统

五、验收标准

  • 任意 PNG/JPG 可一键设为系统桌面壁纸并即时生效，4 种显示模式正确
  • 锁屏设置成功或给出明确指引
  • 定时切换按配置自动轮换，重启后配置保留
  • 动态壁纸在桌面后台流畅播放，全屏游戏/拔电后自动暂停，恢复后自动继续
  • 编辑器可导出含动效的动态壁纸包并被引擎播放
